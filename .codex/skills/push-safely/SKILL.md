# Безопасный push

## Перед отправкой

- Проверить текущую ветку, рабочее дерево, remotes и наличие upstream через `git branch --show-current`, `git status --short` и `git remote -v`.
- Не включать в отправку незакоммиченные или несвязанные изменения. Если они есть, явно сообщить о них и не делать вывод, что они разрешены к публикации.
- Просмотреть коммиты, которые будут отправлены, и убедиться, что целевой remote и ветка ожидаемы.
- Выполнить применимые проверки проекта либо явно указать, какие из них уже были выполнены и почему повторный запуск не нужен.
- Убедиться, что в коммитах нет secrets, локальных конфигураций, generated-файлов и других файлов, запрещённых `AGENTS.md`.

## Отправка

- Выполнять `git push` только по явному запросу пользователя.
- Для первой отправки ветки использовать `git push -u origin <branch>`; для последующих — обычный `git push`.
- Не использовать `--force`, `--force-with-lease`, удаление веток или изменение remote без отдельного явного разрешения пользователя.
- Не обходить hooks и не добавлять `--no-verify`, если пользователь прямо не объяснил причину и не подтвердил это действие.

## Отчёт

- После успешной отправки сообщить remote, ветку и диапазон отправленных коммитов.
- При ошибке остановиться, привести точный безопасный контекст ошибки и предложить следующий шаг; не повторять рискованные команды автоматически.

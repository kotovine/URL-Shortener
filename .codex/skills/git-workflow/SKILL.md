# Git workflow

Этот skill выбирает и упорядочивает специализированные skills; их правила не дублирует.

## Выбор skills

- Для подготовки, проверки или создания коммита прочитать `../commit-conventions/SKILL.md`.
- Для подготовки или выполнения push прочитать `../push-safely/SKILL.md`.
- Для подготовки, создания или обновления pull request прочитать `../create-pull-request/SKILL.md`.
- Если пользователь просит только текст коммита, черновик PR или совет, не выполнять Git-операции.

## Порядок действий

- При запросе «закоммить и запушь» сначала завершить коммит, затем повторно проверить состояние ветки и выполнить push.
- При запросе «закоммить, запушь и создай PR» выполнять: commit → push → PR. Не создавать PR до успешной публикации source branch.
- При запросе «создай PR» без push сначала проверить, существует ли ветка в remote. Если нет, для push требуется явное разрешение пользователя.
- После каждой внешней операции получать актуальное состояние Git и не полагаться на данные, собранные до неё.
- Для составного запроса сначала подготовить все нужные тексты (commit message, title и description PR), показать их одним сообщением и получить явное подтверждение или правки до первой операции, которая использует этот текст.

## Авторизация и остановка

- Явный запрос, перечисляющий несколько действий, разрешает только перечисленные действия и только в указанной логической последовательности.
- Не выводить из такого запроса право на force push, изменение remote, удаление веток, назначение reviewers или изменение статуса PR.
- Если не удаётся достоверно определить source branch, target branch или remote, остановиться и запросить направление до соответствующего действия.
- При ошибке остановиться на текущем шаге, сообщить завершённые действия и безопасный контекст ошибки; не продолжать с последующими действиями автоматически.

## Финальный отчёт

- Кратко сообщить созданный commit hash, remote и ветку после push, а после PR — его URL.
- Отдельно отметить намеренно не включённые или оставшиеся локальные изменения.
